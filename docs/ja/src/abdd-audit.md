# ABDD 監査シート — vX.Y.Z

> **目的.** リリースごとに、GUI が設計書 `aaai_uiux_design.pdf` p.8 の
> Accessible by Default Design (ABDD) チェック観点を満たしているかを記録する
> ファイル。GUI を実機で動かす担当者が「実観測」と「判定」列を埋める。
> RFC 017 の視覚検証カードを補完し、a11y のみに特化した記録となる。
>
> **書き方.**
>   1. GUI をビルド: `cargo build -p aaai-gui --release`。
>   2. 各セクションの「Where」列で示された画面に遷移して期待挙動を確認。
>   3. **実観測** (1 文) と **判定** を以下のいずれかで埋める:
>      - `✅ 合格`
>      - `❌ 不合格` — 追跡用に Issue または RFC 番号を **備考** に記録
>      - `例外` — v1.0 出荷はする。理由を **備考** に記録
>   4. 検証完了後、タイトルの `vX.Y.Z` を実バージョンに置換。
>
> **スコープ.** v1.0.0 が ABDD として保証するのは
> 「キーボードで完結する」「色だけに依存しない」「フォーカスが常に見える」まで。
> スクリーンリーダー対応は §7 に記載の理由で v1.x 以降に延期。

## 2. 色なしでの判別可能性 (設計書 p.8)

モノクロ / グレースケール表示で実行する (Linux: `xrandr --output <name> --gamma 1:1:1` / macOS: 設定 → アクセシビリティ → ディスプレイ → カラーフィルタ → グレースケール)。

| 何を | 期待 | 実観測 | 判定 | 備考 |
|---|---|---|---|---|
| ファイルツリーのステータスアイコン | `✓ ⚠ ✗ ! —` が相互に判別可能 | | | |
| ツールバーの監査ステータス | "Passed" / "Failed" のテキストが判定要素となり、色だけに依存しない | | | |
| 差分ビューアの追加/削除行 | 行頭の `+` / `−` 文字が残っており、それで識別できる | | | |
| インスペクター LineMatch ルールブロック | 行頭 `+` / `−` および `action:` ラベルが維持されている | | | |

## 6. クリック領域 ≥ 44 px (設計書 p.8 ABDD 共通ルール)

**この節は手作業で埋める表ではなく、テストで検証する。** ピクセル測定値を手で
記入した表は、パディングのトークンが変わった時点で古くなる。この節はまさに
そうなって空欄のままだったため、表を廃止した (RFC 115 §S2)。

**ルール。** すべての操作可能なコントロールは、縦横とも **44 × 44 px** に
達すること (WCAG 2.5.5、AAA — プロジェクト独自の ABDD 共通ルール)。
WCAG 2.5.8 (AA) の 24 × 24 は下限であって目標ではない。

**検証。** `crates/aaai-gui/src/target_size_check/` — 次で実行する。

```sh
cargo test -p aaai-gui target_size_check
```

GUI が作るすべての `button`、`text_input`、`text_editor`、`pick_list` を、
4 つのテーマプリセットすべてで検証する。

- **高さ**は正確な値: 文字サイズ × 行の高さ + パディング。パディングと文字
  サイズは view のソースから読み取り、実際のデザイントークンで評価する。view
  のパディング変更や snora の spacing 変更は、そのまま結果に反映される。
- **幅**は、`Length::Fill` のコントロールではレイアウトが決める。内容に応じて
  幅が決まるコントロールでは、左右パディングにラベルの*下限の推定値*を足す
  (テスト中はフォントを読み込まないため)。よって幅の不合格は「未証明」、
  高さの不合格は実測である。

view にコントロールを追加・削除しながら当該モジュールに登録しない (または
登録したウィジェットの種類が実際と違う) と、別のテストが失敗する。そのため
対象集合が気づかれずにずれることはない。

**現状。** ルールはすべてのコントロールに対して検証されるが、**既存の 50 個の
コントロールは基準に達していない** (最小の高さは 22.3〜42.8 px。大半は
インスペクタ、起動画面、各ダイアログのボタン)。これらは除外ではなく**既知の
負債**として、実測の高さとともにモジュール内に列挙している。この一覧は
ラチェットで、**縮むことしか許されない**。一覧にないコントロールが 44 px
未満になる (つまり新しいコントロールは必ず基準を満たす必要がある)、一覧の
コントロールが悪化する、一覧のコントロールが 44 px に達したのに一覧から
削除されていない、のいずれでもテストは失敗する。解消は計画済み: 再スコープ後の
RFC 106 と RFC 115 §S2b。

**snora 自身のコントロール** (トースト閉じる `×` を含む) は、最小のクリック領域を
デザイントークン `Tokens::targets.min` から取る。snora はこのトークンを提供し
既定値を 24 としている。**こちらで**全テーマプリセットについて 44 に設定し
(`design_tokens::TARGET_MIN_PX`)、テストで検証している。トースト `×` は RFC 116
まで (24 × 24 と記録されていたため) この節の除外対象だったが、
現在は除外ではない。

**除外** — それぞれ理由を付けて、モジュール内に明記している。

| コントロール | 除外の理由 |
|---|---|
| 設定・ヘルプ・未保存確認の各ダイアログの背後にある全画面の背景 (3 件) | ウィンドウ全体を覆うクリックで閉じる面であり、狙って押す対象ではない。各ダイアログの「閉じる」「キャンセル」ボタンは個別に検証している。 |

**対象外。** スキャンが検出できない、依存先が作るコントロール (snora のものは
上記のトークンで担保しており、ここでは測っていない)、およびスクリーンリーダー対応 (§7)。

## 7. スクリーンリーダー対応 — v1.0 制限事項

iced 0.14 は OS のアクセシビリティ API (Linux の AT-SPI、Windows の UIA、
macOS の NSAccessibility) にウィジェットツリーを公開しない。iced がこの
フックを提供するまで、スクリーンリーダー利用者にとって aaai-gui は実用的
ではない。

**v1.0.0 はこれを既知の制限事項として宣言する**。スクリーンリーダーが必要な
ユーザーには `aaai` CLI を推奨経路として案内する。

iced が a11y サポートを実装した時点で再評価し、本セクションを埋めるか、
新規 RFC で移行作業を立ち上げる。
